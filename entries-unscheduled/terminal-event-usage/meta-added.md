Python and TypeScript SDKs expose optional `usage` on typed `turn_completed` and `run_completed` events and export `Usage` and `ProviderTokenAccounting`. When the gateway supplies usage, `turn_completed` reports counters for that model call, including provider accounting when present. On `run_completed`, `usage` is the session total so far, not the share for this run. Use the latest total for each session; do not add successive totals.

The SDKs do not compute totals. Missing or null usage stays absent; a reported zero stays zero. If supplied usage is malformed (a required counter is missing, a counter is not a non-negative integer, or provider accounting lacks required fields), the SDK delivers the event without usage. Each affected event produces one warning in the SDK reading it (`meerkat_meta` in Python; `console.warn` in TypeScript). A persistent format mismatch can therefore produce repeated warnings.

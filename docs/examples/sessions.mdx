## Attach host context without merging it into the prompt

Use `injected_context` for ambient facts that should be retained as separate,
typed transcript messages immediately before the user's message. These entries
are visible in transcript reads but excluded from semantic-memory indexing.
Use `transient_turn_context` instead when host-regenerated facts must apply to
one provider request without entering the session transcript at all.

<Tabs>
  <Tab title="JSON-RPC">
    ```json

      "jsonrpc": "2.0", "id": 3,
      "method": "turn/start",
      "params": {
        "session_id": "01936f8a-...",
        "injected_context": [
          "Current incident severity: SEV-1",
          "On-call owner: payments-platform"
        ],
        "prompt": "Recommend the next action"
      }
    }
    ```
  </Tab>

## Resume by ID or alias

CLI supports short prefix matching and relative aliases for resuming sessions.

```bash
# Full UUID
rkat run --resume 01936f8a-7b2c-7000-8000-000000000001 "Keep going"

# Short prefix (git-style, fails on ambiguity)
rkat run --resume 019c8b99 "Keep going"

# Most recent session
rkat run --resume last "Keep going"

# 2nd most recent
rkat run --resume ~2 "Go back to this one"

# Omitting the session value resumes `last`
rkat --resume "Keep going"
```

## Audit and restore transcript revisions

Persistent sessions retain an append-only revision graph when their transcript
head is rewritten. Revision reads and restores keep the same session identity.
These mutations are available over JSON-RPC and the RPC-backed SDKs, not REST.
The target must be idle; `running_behavior: "reject"` fails with
`SESSION_BUSY` instead of racing active work.

<Tabs>
  <Tab title="JSON-RPC">
    ```json
    {
      "jsonrpc": "2.0", "id": 5,
      "method": "session/transcript_revisions",
      "params": { "session_id": "01936f8a-...", "offset": 0, "limit": 50 }
    }
    ```

    Read the active head with `session/transcript_revision` and
    `"revision": "current"`. Restore a retained revision with:

    ```json
    {
      "jsonrpc": "2.0", "id": 6,
      "method": "session/restore_transcript_revision",
      "params": {
        "session_id": "01936f8a-...",
        "revision": "sha256:...",
        "reason": { "kind": "restore", "note": "Restore reviewed head" },
        "running_behavior": "reject"
      }
    }
    ```
  </Tab>
  <Tab title="Python">
    ```python
    revisions = await client.list_session_transcript_revisions(session.id)
    current = await client.read_session_transcript_revision(session.id, "current")

    if revisions.entries:
        restored = await session.restore_transcript_revision(
            revisions.entries[0].revision,
            {"kind": "restore", "note": "Restore reviewed head"},
            expected_parent_revision=revisions.head_revision,
            running_behavior="reject",
        )
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    const revisions = await client.listSessionTranscriptRevisions(session.id);
    const current = await client.readSessionTranscriptRevision(session.id, "current");

    if (revisions.entries.length > 0) {
      const restored = await session.restoreTranscriptRevision(
        revisions.entries[0].revision,
        { kind: "restore", note: "Restore reviewed head" },
        {
          expectedParentRevision: revisions.headRevision,
          runningBehavior: "reject",
        },
      );
    }
    ```
  </Tab>
</Tabs>

`session/rewrite_transcript` and the corresponding SDK methods commit typed
message-range replacements. A rewrite cannot mint the runtime-owned
`compaction_summary` role, while an existing `injected_context` role may be
preserved.

## Event streaming

<Tabs>
  <Tab title="CLI">
    ```bash
    # Basic streaming
    rkat run --stream "Tell me a story"

    ```
  </Tab>
  <Tab title="JSON-RPC">
    Events arrive as `session/event` notifications during a turn:

    ```json
    {
      "jsonrpc": "2.0",
      "method": "session/event",
      "params": {
        "session_id": "01936f8a-...",
        "event": {
          "type": "text_delta",
          "delta": "The capital"
        }
      }
    }
    ```
  </Tab>
  <Tab title="REST">
    ```bash
    # SSE stream (connect before starting a turn)
    curl -N http://localhost:8080/sessions/01936f8a-.../events
    ```

    Events arrive as Server-Sent Events with types like `text_delta`, `tool_call_requested`, `turn_completed`, and `done`.
  </Tab>
  <Tab title="MCP">
    ```json
    {
      "name": "meerkat_run",
      "arguments": {
        "prompt": "Tell me a story",
        "stream": true
      }
    }
    ```

    When `stream: true`, the MCP server sends progress notifications with `AgentEvent` payloads during execution.

    For long-running or autonomous sessions, use the managed event stream tools instead:

    ```json
    // Open a stream
    {"name": "meerkat_event_stream_open", "arguments": {"session_id": "01936f8a-..."}}
    // => {"stream_id": "evt-..."}

    // Poll for events (blocks until next event or timeout)
    {"name": "meerkat_event_stream_read", "arguments": {"stream_id": "evt-..."}}

    // Close when done
    {"name": "meerkat_event_stream_close", "arguments": {"stream_id": "evt-..."}}
    ```
  </Tab>
  <Tab title="Python">
    ```python
    # Streaming on session create
    async with client.create_session_streaming("Tell me a story") as stream:
        async for event in stream:
            match event:
                case TextDelta(delta=chunk):
                    print(chunk, end="", flush=True)
        result = stream.result

    # Streaming on a follow-up turn
    async with session.stream("Continue the story") as events:
        async for event in events:
            match event:
                case TextDelta(delta=chunk):
                    print(chunk, end="", flush=True)
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    // Streaming on session create
    const stream = client.createSessionStreaming("Tell me a story");
    for await (const event of stream) {
      if (event.type === "text_delta") {
        process.stdout.write(event.delta);
      }
    }
    const result = stream.result;

    // Streaming on a follow-up turn
    for await (const event of session.stream("Continue the story")) {
      if (event.type === "text_delta") {
        process.stdout.write(event.delta);
      }
    }
    ```
  </Tab>
  <Tab title="Rust">
    ```rust
    let (tx, mut rx) = mpsc::channel::<AgentEvent>(100);

    tokio::spawn(async move {
        while let Some(event) = rx.recv().await {
            match event {
                AgentEvent::TextDelta { delta } => print!("{}", delta),
                AgentEvent::TurnCompleted { usage: Some(usage), .. } => {
                    // Per-call usage: `accounting` names the resolved model and
                    // the normalized presented input for this one call.
                    println!(
                        "\n[{}: {} tokens]",
                        usage.accounting().model,
                        usage.normalized_total_tokens()
                    );
                }
                _ => {}
            }
        }
    });

    let result = agent.run_with_events("Tell me a story".into(), tx).await?;
    ```
  </Tab>
</Tabs>

<Note>
`turn_completed` carries usage for one provider call while `run_completed` and
`RunResult.usage` carry the session-cumulative total, and their `input_tokens`
fields use different denominators. Read
[Usage accounting](/reference/usage-accounting) before aggregating either.
</Note>

    ```rust
    println!("generation: {}", snapshot.generation);

    // Replace with optimistic concurrency (generation CAS)
    runtime.set(new_config, Some(snapshot.generation)).await?;
    ```

## Realm selection

Realms scope sessions and config. Surfaces see the same state only when both
the `realm_id` and resolved physical provider/root match. Realm is set at
**startup** for server surfaces (RPC, REST, MCP) and **per-command** or
**per-connection** for CLI and SDKs.

<Note>
Without an explicit override, the CLI derives a stable workspace realm from
the context root (normally the current directory) and stores it under the
project-local `.rkat/realms` root. RPC, REST, MCP, and SDK connections create a
new opaque realm unless the caller supplies one.
</Note>

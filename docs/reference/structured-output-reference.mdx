Use this page when you need exact structured-output terminology and types rather than the task-first usage guide.

## Core types

| Type | Contract |
|------|----------|
| `OutputSchema` | Owns `schema`, optional `name`, `strict`, `compat`, and `format`. |
| `MeerkatSchema` | Normalized JSON Schema value. The root must be an object. Object-typed nodes gain an explicit `properties` object/map and a `required` array. |
| `SchemaCompat` | `Lossy` drops provider-unsupported schema features with warnings; `Strict` rejects them. |
| `SchemaFormat` | Currently `MeerkatV1`. |
| `SchemaWarning` | Provider, JSON path, and explanation for a lossy lowering decision. |
| `CompiledSchema` | Provider-lowered validation schema plus warnings. Local validation runs against it. An adapter whose native schema slot rejects some keywords (Anthropic `output_config.format`) sends a further-lowered copy in that slot only. That copy drops only keywords local validation still enforces (plus annotations such as `discriminator`), so it adds no warnings and `Strict` does not reject them. |

## Request-side controls

| Field | Default | Meaning |
|-------|---------|---------|
| `output_schema` | `None` | Declared extraction schema. When absent, there is no extraction phase. |
| `structured_output_retries` | `2` | Validation retries after the first attempt, for at most three extraction calls by default. |

Provider adapters compile the normalized schema before extraction. Strictness
is a provider-lowering request; local JSON Schema validation still runs before
Meerkat accepts the result.

## Result-side fields

| Field | Meaning |
|-------|---------|
| `RunResult.text` | Committed main-turn assistant output after provider schema compilation succeeds. Extraction does not replace it. |
| `RunResult.structured_output` | Validated JSON value on success. |
| `RunResult.extraction_error` | Main output, attempts, and reason when the post-main extraction phase fails. |
| `RunResult.schema_warnings` | Lossy provider-compilation warnings, when any. |
| `RunResult.turns` | Includes extraction attempts. |

Provider schema compilation happens before the main output is saved into the
result. A compilation failure can therefore return the typed extraction failure
with an empty `RunResult.text`; output retention applies to failures after
schema compilation succeeds.

## Event ordering

After provider schema compilation succeeds, a schema-bearing run has two
terminal observability stages:

1. The normal agentic turn completes and emits `run_completed` with
   `extraction_required: true`. `result` is the main assistant output.
2. Extraction emits exactly one follow-up terminal event:
   `extraction_succeeded` with `structured_output` and optional
   `schema_warnings`, or `extraction_failed` with `last_output`, `attempts`,
   and `reason`.

Extraction does not emit ordinary text or `turn_completed` events. Both
outcome events carry `request_usage`: one per-call usage row for each answered
extraction request, including attempts that failed validation. Extraction
failure does not emit `run_failed`; the main run already completed, and the
returned `RunResult` carries `extraction_error`.

Provider schema compilation happens before these success-shaped boundaries. A
compile failure emits `extraction_failed` directly and emits neither
`turn_completed` nor `run_completed` first.

## Validation note

Schema validation depends on the `jsonschema` feature. A build without that
feature fails closed with typed `InvalidOutputSchema` when an output schema is
configured. Meerkat never marks merely parsed, unvalidated JSON as structured
output.

Each extraction attempt runs with no tools. Core requests temperature `0.0`;
provider lowering may omit it when the provider/model does not support the
parameter. This is not a deterministic-output guarantee. Markdown code
fences are stripped before parsing. A provider may wrap a named root object in
the schema name; Meerkat unwraps that envelope only when the inner object is a
clearly better match and the wrapper key is not itself declared by the schema.

- Reasoning effort and an agent's own model switch (0.9.15, 0.9.16 and this release): when an agent switches its session to another model with its built-in tool `brain_swap` while the session holds a reasoning effort level, the switch is carried out before the next turn without asking whether the new model takes that level. If it does not, the session is left on the new model with a level that model refuses, and the next turn and every later one is refused with invalid params until the level or the model is changed: JSON-RPC `-32602`, HTTP 400, CLI exit 2 with `INVALID_PARAMS`; the error's data has the kind `reasoning_effort_refused`, and its text reads, for a level the new model's source does not list, "reasoning effort '<level>' is not supported by <provider> model '<model>' on <route>; supported: <levels>". Nothing is sent to a provider, and the level is not lowered by itself. No JSON-RPC, REST or MCP request stages such a switch: only the agent's tool does (a Rust host's own `request_switch_turn` has the same effect). A session has the tool when its host can carry out the switch, more than one model is reachable, the tool is enabled (it is by default) and no client override is set; `rkat` builds its sessions so (which other surfaces' sessions have it, and Meta, were not traced). To get the session running again, clear the level or set one the new model takes with the next request, or name another model: `reasoning_effort` on `turn/start` and `mob/turn_start`, REST `POST /sessions/{id}/messages` and MCP `meerkat_resume` (a level sets it, `{"action":"clear"}` removes it); `rkat run --resume <SESSION> --no-reasoning-effort "<PROMPT>"` or `--reasoning-effort <LEVEL>`. (Read from the source at the 0.9.16 tag, where a test pins the behaviour, and the same files are unchanged at this release's candidate; 0.9.15 by a search of every 0.9 tag by content; not run. That a changed level or model ends the refusal is read from the source; the calls named for it are those of the documentation of that release and were not run for this case.) A fix is planned.

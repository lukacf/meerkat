Follow-ups from the architecture review of the #1102 actor-loop redesign (branch fix/mob-actor-member-work-off-loop; review notes in the lead's /tmp/rb/arch-review-1102.md on the release VM). Approved for 0.8.34; these are the deferred items.

1. **Reload should go through the member lane and the registration witness.** `spawn_member_registration_reload` (actor.rs ~16127-16196) runs concurrently with the member's delivery task and decides `discard_live_session` from two non-atomic reads (`session_has_no_executor_registration` then `has_live_session`). Once fix/stale-discard-observability lands (RuntimeSessionRegistrationWitness, until-terminal discard), route the reload through the member's single-flight lane and use the witness seam instead of the racy reads.
2. **`MemberReloadRequired` needs its own wire error code.** It maps to `ErrorCode::SessionBusy` / failure class `TargetBusy` while the JSON says `retryable: false`. Add a distinct `ErrorCode` (e.g. `member_reload_required`), regenerate schemas, and mirror it in the SDK error-category parity sets.
3. **Remaining inline arms** (from the analyst report section 4 follow-ons): `finalize_spawn_activate`, `Wire`/`Unwire`/`WireMembersBatch`, `Retire`/`Respawn`/`MemberLive*`, the placed `TurnCompleted` pump ensure (now bounded by the 2 s join fix but still inline), post-commit resume topology reconciliation. Also `MachineCleanupTaskSpawner` hardening (single-worker runtime) and a timeout on `StdioCallbackBridge` stdout sends.
4. Idioms: `MEMBER_RETIRE_TOTAL_TIMEOUT` reused as the reload deadline (own const); bare `u64` tickets for the admission lane and resume fan-out (newtypes).

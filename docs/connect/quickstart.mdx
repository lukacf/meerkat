## Standalone CLI

Install [Meerkat Core 0.9.10](https://github.com/lukacf/meerkat/releases/tag/v0.9.10)
for ordinary `rkat` agent work after setup. The Connect archive supplies its own Python, Node/npm, integration
library and setup resources; you do not need to install those separately.

<Steps>
  <Step title="Download and extract the complete CLI archive">
    Download the CLI archive and its `.sha256` companion:

    ```sh
    platform=linux-x86_64 # 0.9.10 has no macos-arm64 archive yet.
    archive="meerkat-connect-0.9.10-$platform.tar.gz"
    release=https://github.com/lukacf/meerkat/releases/download/connect-v0.9.10
    curl -fLO "$release/$archive"
    curl -fLO "$release/$archive.sha256"
    ```

    On macOS, verify it with `shasum -a 256 -c "$archive.sha256"`; on Linux,
    use `sha256sum -c "$archive.sha256"`. Continue only when it reports success:

    ```sh
    tar -xpf "$archive"
    ```

    Keep the complete extracted directory together, including its executable permissions and `libexec` resources.
  </Step>
  <Step title="Open Connect and choose the realm">
    Run the supplied binary for your platform from the extracted location:

    <Tabs>
      <Tab title="Linux x86_64">
        ```sh
        ./meerkat-connect-linux-x86_64/bin/meerkat-connect
        ```
      </Tab>
      <Tab title="Apple Silicon macOS">
        ```sh
        ./meerkat-connect-macos-arm64/bin/meerkat-connect
        ```
      </Tab>
    </Tabs>

    If stored realms are listed, enter a realm number, or enter `new` and then
    a name. With no stored realms, enter the new name directly. Check the printed
    realm name and storage path, especially if the same name appears more than
    once. You can instead pass `--realm work` to select it explicitly. If that
    name exists at multiple roots, also pass `--state-root "/exact/storage/root"`
    using the chosen path, or select its numbered entry.
    Review the setup helper's access, complete model
    setup if prompted, and review the assistant's model and tools. These startup
    reviews are separate from each integration's installation and access.
  </Step>
  <Step title="Describe and approve the integration">
    For example: "Add an integration that reads Hacker News and give the normal
    agent read-only access." The agent can choose a catalog entry or investigate
    a supported package outside the catalog.

    Review the software, service account, agent, exact operations and access
    duration. Complete sign-in or key entry only in the protected controls.
    Model credentials and service credentials are separate; neither belongs in chat.
  </Step>
  <Step title="Use it from an ordinary agent">
    Read the final configuration, credential and grant outcomes. After successful
    finalization and return to the prompt, enter `/quit` and wait for normal exit.
    From the same working directory, start `rkat` in that realm:

    ```sh
    rkat --realm work run --wait-for-mcp --mcp-auth stored "Read the three leading Hacker News stories and summarize them."
    ```

    Replace `work` with your selected realm and the quoted request with your
    actual task. This starts a fresh agent session using the realm's saved integration configuration and current permissions.
    If the chooser listed that name at multiple storage roots, also pass
    `--state-root "/exact/storage/root"` to `rkat`, using the path printed by
    Connect. The realm name alone cannot select between those stored copies.
  </Step>
</Steps>

If you deliberately used custom roots or a different model binding, follow the
[matching realm and model instructions](/connect/guides/request-an-integration).
Ordinary use does not require custom directories or a separate Connect server.

## Integrated Console

Open your Connect-enabled application through its normal entrypoint and sign in. The application supplies the Console, native runtime and setup panel.

1. Send the complete task to the original agent, including the service, resources
   and intended result.
2. When the setup panel offers **Start service setup**, open it. Review the
   selected software and access, and answer any setup questions.
3. Approve only the reviewed installation and operations. Use **Approve & Save**
   and its protected credential fields when the panel requests service keys;
   never send credentials as a chat message.
4. Read the setup result and the original agent's continuation. Follow the agent as it uses the integration to complete your request.

The application retains the original conversation and setup progress, so you can return to the task after completing the required account and access steps.

## Updating an existing application

Connect 0.9.10 does not support in-place updates that change an application's
tool policy, definition, instructions or runtime; Forge's Stage refuses them,
so keep the existing installation and state. Do not extract a new archive over
it. See [platforms and installation options](/connect/availability) for the released
scope.

## If setup stops or access changes

Accepted configuration, credentials or grants can remain saved after a later
failure or cancellation. Do not infer rollback or repeat an uncertain action.
Read the reported outcome and return to Connect in the same realm or application
for its supported management flow. See [request and manage access](/connect/guides/request-an-integration)
and [connection management](/connect/guides/manage-connections).

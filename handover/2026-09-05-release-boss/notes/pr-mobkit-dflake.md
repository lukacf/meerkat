Fixes #398 and #401 at the root; no retries-until-green, no longer sleeps, no ignores.

**#401 swarm_integration (test-only).** The panic is at `mob_handle().stop()`: spawning the worker starts its autonomous kickoff turn, and when `stop()` arrives while that run is live the mob actor issues a boundary cancel that the machine admits and dispatches to the test's `CheckpointerCancelProbeSessionService`. The probe forwarded `interrupt_run_with_machine_authority` but inherited the `Err(Unsupported)` trait defaults for `cancel_after_boundary_with_machine_authority` and its siblings, so it refused an admitted cancel on its own authority. When the kickoff had already finished nothing was dispatched, hence load-dependent. Fix: forward them like the lib's `delegate_mob_session_service!` does. Reproduced by oversubscribing the binary: 369/5120 failures before, 0/5120 after; serial 40/40.

**#398 flow-editor smoke (product race).** `mobkit/mobpacks/source`, validate and deploy-plan carry the optimistic draft guard of the registry row the UI last saw. Entering Graph mode autosaves the document; when that save has bumped the server revision but its response is not yet applied to the row, the render for the just-opened source panel is refused with `draft revision conflict ... expected 1, found 2`, and the panel stays empty behind the validation sheet, which is what the smoke waited 120 s on. Authoring operations already retried this exact race once without the guard; read-only renders did not. Fix in `packages/flow-editor-core/src/rpc/doc-ops.ts`: source, validate and deploy-plan (`execute: false`) go through `callRenderRpc`, which retries once without only the guard keys and the same document; a real deploy keeps the guard. `flow-editor-dist` regenerated. Reproduced deterministically by delaying only the autosave response 2.5 s (empty panel + conflict sheet before, both sections rendered after); unmodified smoke 30/30 against the rebuilt binary; regression test fails on the old `doc-ops`.

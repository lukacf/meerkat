Fixes #1103, reported by the HomeCore agent while moving HSNS from meerkat-sdk 0.7.10 + rkat-rpc 0.7.11 to the 0.8.33 pair.

- **Python SDK: `close()` treats a vanished rkat-rpc child as already closed.** `close()` checks `returncode` first, guards `terminate()`/`kill()` against `ProcessLookupError`, waits a bounded time after kill, and is idempotent, so it never raises over the caller's original `MeerkatError` (HSNS logged `ProcessLookupError()` for a day of jobs).
- **Python SDK: rkat-rpc stderr is drained and its tail reported.** A bounded 16 KB ring drains stderr for the child's lifetime (a chatty child under `RUST_LOG` can no longer block on a full pipe); on stdout EOF the dispatcher waits up to 1 s for stderr EOF and fails waiters with `CONNECTION_CLOSED` carrying `rkat-rpc process closed; stderr tail:` plus `details.stderr_tail`, and the recorded transport fault carries the same so later requests report it too.
- **rkat-rpc, rkat-rest and rkat-mcp print fatal startup errors in Display form.** All three had `fn main() -> Result<(), Box<dyn Error>>`, so a storage refusal printed as `Error: Store(UnledgeredDomainObjects { .. })` and the remedy sentence naming `storage migrate --apply --bridge-pre-0-8-10`, which only Display carries, was never shown. They now route through `meerkat::surface::report_fatal_error` (Display chain with `caused by:` lines, binary-name prefix, exit 1); rkat-mcp still installs its stderr tracing subscriber first.

Tests: Python 542 passed (14 new in `tests/test_client_child_process.py`, including a 400 KB chatty-child case); Rust `surface::fatal_error` unit tests and a `binary_fatal_error_display` test per binary that spawns the real binary and asserts the Display line and exit status. Clippy clean. Pre-push gate passed on the release VM.

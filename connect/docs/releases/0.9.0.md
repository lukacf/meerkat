# Meerkat Connect 0.9.0

Connect gives agents an integration library and a way to discover tools beyond
it. The standalone CLI guides installation and authentication into a native
realm. In a compatible application's Console, the original agent can delegate
setup and continue its task once the integration is ready.

The library contains 101 adopted integration identities on macOS and 100 on
Linux. Playwright is excluded on Linux. Each profile defines its supported
operations, configuration and authentication requirements.

## Try the CLI

Run `meerkat-connect --realm work` and ask it to add a read-only Hacker News
integration. Review and finish setup, enter `/quit`, then start a fresh ordinary
agent from the same project directory:

```sh
rkat --realm work run --wait-for-mcp --mcp-auth stored \
  "Read the three leading Hacker News stories and summarize them."
```

The realm and project context must match setup. For the integrated Console,
give the original agent a task requiring an integration. It can research a
supported package, request installation and access approval, and continue in
the same conversation. See [Console steps](../site/quickstart.mdx#integrated-console).

## Compatibility and limits

The native dependencies are [Core 0.9.0 at a00bafaf](https://github.com/lukacf/meerkat/commit/a00bafaf1d862fb41112ff1f30312b350ad05246)
and [Meta 0.9.0 at b275e0ed](https://github.com/lukacf/meerkat-meta/commit/b275e0ed4fe61cf4ff43d16691c54efb17812919).
The source locks published crate versions and includes the exact unpublished
Core code generator. See [building](../../BUILDING.md) and
[source provenance](../../SOURCE-PROVENANCE.md).

Supported composition surfaces are Native Rust, CLI and JSON-RPC with Python and
TypeScript. MCP servers used as integrations are included; REST and an outer
MCP Connect entry point are deferred. Broad frontend/custom extension adoption,
remote deployments and universal account registration are follow-up work.

Library counts cover declared operations and setup profiles, not successful
live authentication for every provider. Open-ended acquisition accepts supported
package forms and validated dependency closures; it cannot promise every
package or account will work. The precise predecessor-store upgrade limitation
and other deferred paths are in [follow-up.md](follow-up.md).

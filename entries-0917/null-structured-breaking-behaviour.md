- Behaviour-only (not measured by the gate): a replayed `interaction_complete` event of a run whose structured output is JSON null now carries "structured_output" with the value null; before, the member was absent after the reread. It concerns a session that ran a directed input (one with an interaction id, such as a mob's placed turn or a flow step) under an output schema that admits null, where its events are read again from the durable event log: RPC `events/list_since` on that session, and, for a mob member that runs on another host, `mob/stream_open` (`structuredOutput` in the TypeScript SDK). The live event carried the null on both releases. Code that tests the member's presence on the replayed event (`"structured_output" in event`, `!== undefined`) now takes the branch for a present member with the value null; code that tests the value is not affected. A `run_completed` event does not carry the member where the output comes by the extraction step: there the null is on `extraction_succeeded`, before and after, so a session started with `turn/start` on `rkat-rpc` shows no difference (shown by runs on the published 0.9.16 and on a build of this release's source). No declared type and no generated file changes; the Python SDK gives `None` either way. See Fixed, "A structured output that is JSON null". (That a reread keeps the member: shown by a test.

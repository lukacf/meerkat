- Structured output that is JSON null (0.8.11 through 0.9.16 by the source: the check that refuses the record and the field's form are at every release tag from 0.8.11, by a search of all tags by content; 0.8.0 to 0.8.10 hold an earlier check and were not read; the way a null output reaches the check was read at 0.9.16 only; run on 0.9.16 only; added 2026-11-17): when a run's output schema admits null at its root and the model answers null, on a session whose runtime state is kept in SQLite (a Meta gateway keeps it so too: read from the source, not run on a gateway), the run completes and the record of its input can no longer be read from the store (one record per such run; the log can name it as a row that `no longer decodes`, with `digest mismatch` in the detail). In runs on the 0.9.16 release commit that did no harm by itself: the session and its history read whole, a resume in a new process ran one more turn with the earlier turns, an export, a compaction and an archive answered, and a second session of the realm was untouched; an operator who sees those log lines while every read answers has nothing to do. The harmful case: if the host process ends between that run's commit and its finalization (typically 20 to 40 ms in the author's runs; 1 to 260 ms seen), the session is refused at the next start, and at every later one by the state the store is left in: the log holds `failed to recover runtime driver during registration` with `pending terminal owner row read failed: Store read failed: terminal completion candidate digest mismatch`, and a prompt is answered `Runtime not ready: destroyed`. No way past it is known on the released code. (Shown by a run of the runtime with a SQLite store and two processes, the first ended at that point by a test executor; a host ended there by itself was not run. The same end after a run with a non-null result starts and runs. One later start was run.) Until fixed: use an output schema whose root does not admit null; a root with no `type` admits it. Not affected: the in-memory store (read from the source). On a store the host provides it needs no such moment, read from the source and not run: any finished run with a null structured output leaves a record that the store's typed import refuses, and the session is refused at its next use. Not run: root forms that admit null other than an object-or-null root. Not traced: whether anything besides a start refuses a session that holds such a record. A fix is written and is planned for 0.9.17.

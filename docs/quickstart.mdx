## Install

<Tabs>
  <Tab title="CLI">
    ```bash
    brew install lukacf/meerkat/rkat
    ```

    The tap supports macOS and Linux and installs `rkat`, `rkat-rpc`,
    `rkat-rest` and `rkat-mcp`. Without Homebrew, use the release archives
    (see [Linux without Homebrew](#linux-without-homebrew)).
  </Tab>
  <Tab title="Python">
    ```bash
    pip install meerkat-sdk
    ```

    The SDK resolves and can download a compatible `rkat-rpc` by default.
  </Tab>
  <Tab title="TypeScript">
    ```bash
    npm install @rkat/sdk
    ```

    The SDK resolves and can download a compatible `rkat-rpc` by default.
  </Tab>
  <Tab title="Web/WASM">
    ```bash
    npm install @rkat/web
    ```

    The web package runs Meerkat in the browser rather than spawning
    `rkat-rpc`. Continue with the [Web/WASM example](/examples/wasm).
  </Tab>
  <Tab title="Rust">
    Meerkat is pre-1.0, so exactly pin the crate family and bump deliberately:

    ```toml
    [dependencies]
    meerkat = { version = "=0.8.51", features = ["sqlite-store", "session-store"] }
    meerkat-store = "=0.8.51"
    meerkat-tools = "=0.8.51"
    tokio = { version = "1", features = ["full"] }
    ```

    Start with the [Rust SDK overview](/rust/overview) for runtime-backed
    `SessionService` construction.
  </Tab>
  <Tab title="Cargo CLI">
    ```bash
    cargo install rkat
    ```

    This builds from source and installs `rkat` only. It needs Rust 1.94 or
    later, a C compiler and libc headers (for bundled SQLite and aws-lc-sys),
    and several GiB of RAM; see [Building and deploying](/guides/deploying).
    The other binaries come from their own crates: `cargo install
    meerkat-rpc` (`rkat-rpc`), `meerkat-rest` (`rkat-rest`) and
    `meerkat-mcp-server` (`rkat-mcp`).
  </Tab>
</Tabs>

### Linux without Homebrew

Each GitHub release has one archive per binary per target, plus
`checksums.sha256`. Download the binaries you need, verify them, and put
them on your `PATH`:

```bash
VERSION=<version>   # for example 0.8.51
TARGET=x86_64-unknown-linux-gnu   # or aarch64-unknown-linux-gnu
BASE=https://github.com/lukacf/meerkat/releases/download/v$VERSION
curl -LO "$BASE/checksums.sha256"
for bin in rkat rkat-rpc; do
  curl -LO "$BASE/$bin-$VERSION-$TARGET.tar.gz"
done
sha256sum --ignore-missing -c checksums.sha256
for bin in rkat rkat-rpc; do
  tar -xzf "$bin-$VERSION-$TARGET.tar.gz"
done
mkdir -p ~/.local/bin && mv rkat rkat-rpc ~/.local/bin/
```

Add `rkat-rest` or `rkat-mcp` to the loops if you need them. `rkat-rpc` is
the binary the Python and TypeScript SDKs drive. The Linux binaries need
glibc 2.31 or later; musl distributions such as Alpine are not supported
(see [Linux glibc floor](/guides/deploying#linux-glibc-floor)).

## Configure One Provider

The fastest path is a dedicated Meerkat environment variable:

<CodeGroup>

```bash OpenAI
export RKAT_OPENAI_API_KEY="sk-..."
```

```bash Anthropic
export RKAT_ANTHROPIC_API_KEY="sk-ant-..."
```

```bash Gemini
export RKAT_GEMINI_API_KEY="AIza..."
```

</CodeGroup>

Provider-native names also work. For OAuth, Azure, cloud IAM, managed-store
credentials, and tenant-scoped bindings, see [Auth](/guides/auth).

<Warning>
Meerkat's OpenAI/global catalog default is `gpt-6-astra`. Explicit model and
binding defaults are preserved. Catalog support does not guarantee API access
or support through Azure, Copilot, or custom backends. Select an available
model explicitly or configure a binding `default_model` when needed.
</Warning>

## Run A First Session

<Tabs>
  <Tab title="CLI">
    With the OpenAI variable above:

    ```bash
    rkat run "What is the capital of France? Answer in one sentence."
    ```

    With another provider, select a matching model:

    ```bash
    rkat run --model claude-sonnet-4-6 "Explain async/await"
    rkat run --model gemini-3.8-flash "Explain async/await"
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import asyncio
    from meerkat import MeerkatClient


    async def main():
        async with MeerkatClient() as client:
            session = await client.create_session(
                "What is the capital of France? Answer in one sentence."
            )
            print(session.text)


    asyncio.run(main())
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import { MeerkatClient } from "@rkat/sdk";

    const client = new MeerkatClient();
    await client.connect();
    const session = await client.createSession(
      "What is the capital of France? Answer in one sentence.",
    );
    console.log(session.text);
    await client.close();
    ```
  </Tab>
</Tabs>

The SDKs connect to `rkat-rpc`; the CLI constructs the same runtime-backed
session in-process.

## Share State Across Surfaces

CLI commands derive a stable workspace realm by default. A bare RPC/REST/MCP
server or SDK connection creates a fresh isolated realm. Pass one explicit ID
when several processes should see the same sessions and config:

```bash
rkat --state-root /srv/meerkat/realms --realm team-alpha run "Draft a release note"
rkat-rpc --state-root /srv/meerkat/realms --realm team-alpha
```

```python
import asyncio
from meerkat import MeerkatClient


async def main():
    client = MeerkatClient()
    try:
        await client.connect(realm_id="team-alpha", state_root="/srv/meerkat/realms")
        session = await client.create_session("Draft a release note")
        print(session.text)
    finally:
        await client.close()


asyncio.run(main())
```

```typescript
const client = new MeerkatClient();
await client.connect({
  realmId: "team-alpha",
  stateRoot: "/srv/meerkat/realms",
});
```

The processes must also resolve the same physical storage root/provider. See
[Realms](/concepts/realms).

## Add An MCP Server

```bash
rkat mcp add filesystem -- \
  npx -y @modelcontextprotocol/server-filesystem /tmp
rkat run --wait-for-mcp "List the files in /tmp"
```

Config changes apply to newly built/resumed agents. MCP servers normally
connect in the background and tools appear as each server becomes ready;
`--wait-for-mcp` makes the first prompt wait for configured servers.

For a remote streamable-HTTP server (replace the example URL with the service
you use):

```bash
rkat mcp add --transport http knowledge https://mcp.example.com
rkat mcp login knowledge
rkat run --wait-for-mcp "Search the knowledge base for onboarding docs"
```

## Bound One Run

```bash
rkat run \
  --max-tokens 4000 \
  --max-duration 30s \
  --max-tool-calls 5 \
  "Inspect this project and summarize the main risks"
```

- `--max-tokens` caps LLM output per turn.
- `--max-tool-calls` bounds tool use for the run.
- `--max-duration` bounds the run's agent lifetime; a deadline is a hard
  terminal failure rather than a warning.

For aggregate turn deadlines, lifetime token budgets, retry policy, and
admission limits, use realm [configuration](/concepts/configuration).

## Add Built-In Capabilities

The `full` preset enables the product CLI's broad tool composition, including
shell, MCP, skills, comms, schedules, WorkGraph, and mob orchestration where
compiled:

```bash
rkat run --tools full \
  "Create a small mob to inspect src/, collect the findings, and summarize them."
```

Use `--allow-tool` and `--block-tool` for a narrower first-turn scope. Shell
access and other effectful tools should be granted deliberately.

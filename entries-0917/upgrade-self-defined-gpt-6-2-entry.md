- A configuration that defines `gpt-6.2-astra` or `gpt-6.2-sol` itself (a `[models."gpt-6.2-sol"]` entry, for example because you ran the model on 0.9.16 before the catalog listed it) must drop that entry when upgrading: the catalog now has both ids, and a second definition of a model id is refused with "model id '<id>' must be unique across built-in, custom, and self-hosted entries". The refusal comes when the configuration is loaded, not when the model is first used, so with such an entry nothing starts: every `rkat` command that loads the runtime configuration answers "Invalid runtime config: " and that message, and `rkat-rpc`, the REST server and a Meta gateway refuse to start. An entry in a mob definition is refused when one of the mob's members is built. Without the entry the catalog row serves the model with its own limits and reasoning effort levels (see Added). (The rule and where it is applied are read from the source. The rule was met by a run on the published 0.9.16 with an id that release's catalog lists, where the configuration command refused the entry. With these two ids on this release it is not run yet.)
